# HQ-VP-10.05 — EtherChannel Member Failure — Session Record

## Session record

**Evidence type:** session record  

The original 10.05 Cisco CLI was captured during the live test session on
3 October 2026. The full terminal block was not saved as a standalone file, but
the test results and several exact log lines were retained in the Phase 10
session material.

The two `event-log-recovered` files in this folder are verbatim extracts from
later saved Cisco logging buffers. They preserve the original 10.05 link
events and LACP suspension message.

## Member selection

Po20 member pairs:

- hq-a1 Gi1/0 <-> hq-d2 Gi0/0
- hq-a1 Gi1/1 <-> hq-d2 Gi0/1

Traffic-counter change used to select the member:

```text
hq-d2 Gi0/0: 7682 -> 7800  (+118)
hq-d2 Gi0/1: 7461 -> 7478  (+17)
```

## One-sided run

hq-d2 Gi0/0 was shut at one end only.

Retained results:

```text
initial ping: 0/20
SLA101: Timeout, 49 successes / 177 failures
SLA102: OK, 230 successes / 0 failures
```

The later hq-a1 logging capture preserved the exact LACP message:

```text
*Oct  3 18:17:57.861: %EC-5-L3DONTBNDL2: Gi1/0 suspended: LACP currently not enabled on the remote port.
```

## Bilateral rerun

The same member pair was then removed at both ends.

Retained bundle state:

```text
Po20(SU)

hq-a1:
  Gi1/0(D)
  Gi1/1(P)

hq-d2:
  Gi0/0(D)
  Gi0/1(P)

Port-channel20 up/up
```

Traffic and probe checkpoint:

```text
ping: 20/20

SLA101: 80 successes / 5 failures, latest result OK
SLA102: 82 successes / 5 failures, latest result OK
```

## Recovery

The failed member was restored at both ends.

The session record retained:

```text
hq-a1 Gi1/0(P) Gi1/1(P)
hq-d2 Gi0/0(P) Gi0/1(P)
ping: 5/5
SLA101 latest result: OK
SLA102 latest result: OK
```
