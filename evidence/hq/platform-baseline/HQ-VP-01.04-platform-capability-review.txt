HQ-VP-01.04 — Platform Capability Review
Date: 2026-09-20
Site: HQ Campus — OSPF Area 10

Purpose
-------
Confirm that the representative CML image families expose the platform capabilities
required by the approved HQ design before feature implementation begins.

Representative devices
----------------------
IOSvL2 capability checks: hq-d1
IOSv capability checks:   hq-r1

This record confirms command/parser availability and clean baseline behaviour only.
Operational feature behaviour will be verified in the later implementation phases.

======================================================================
IOSvL2 — hq-d1
======================================================================

1. EtherChannel / LACP command family

Command:
show etherchannel summary

Observed:
Number of channel-groups in use: 0
Number of aggregators:           0

Interpretation:
EtherChannel operational show support is present and the clean baseline contains
no configured channel-groups.

Command:
channel-group 10 mode ?

Observed:
  active     Enable LACP unconditionally
  auto       Enable PAgP only if a PAgP device is detected
  desirable  Enable PAgP unconditionally
  on         Enable Etherchannel only
  passive    Enable LACP only if a LACP device is detected

Result:
LACP active/passive modes are available for the planned Layer 2 EtherChannels.


2. Spanning Tree

Command:
show spanning-tree summary

Observed:
Switch is in pvst mode

Command:
spanning-tree mode ?

Observed:
  mst         Multiple spanning tree mode
  pvst        Per-Vlan spanning tree mode
  rapid-pvst  Per-Vlan rapid spanning tree mode

Result:
Rapid PVST+ mode is available. The baseline remains in PVST mode until the
dedicated spanning-tree implementation phase.


3. Routed physical interfaces

Command:
no switchport ?

Observed:
  <cr>

The command was briefly applied to GigabitEthernet0/0 as a capability check,
then immediately reversed with:

switchport

Verification:
show interfaces GigabitEthernet0/0 switchport

Observed:
Switchport: Enabled

Result:
The IOSvL2 image supports converting a physical switchport to a routed port, and
the test interface was restored to its original Layer 2 baseline state.


4. HSRP

Command:
standby 112 ?

Observed:
  authentication  Authentication
  follow          Name of HSRP group to follow
  ip              Enable HSRP IPv4 and set the virtual IP address
  ipv6            Enable HSRP IPv6
  mac-address     Virtual MAC address
  name            Redundancy name string
  preempt         Overthrow lower priority Active routers
  priority        Priority level
  timers          Hello and hold timers
  track           Priority tracking

Result:
The HSRP command family exposes the IPv4 virtual IP, priority and preempt
functions required by the approved HQ gateway design.


5. Interface-specific OSPF controls

Command:
ip ospf ?

Observed:
  <1-65535>            Process ID
  authentication       Enable authentication
  authentication-key   Authentication password (key)
  cost                 Interface cost
  database-filter      Filter OSPF LSA during synchronization and flooding
  dead-interval        Interval after which a neighbor is declared dead
  demand-circuit       OSPF Demand Circuit
  flood-reduction      OSPF Flood Reduction
  hello-interval       Time between HELLO packets
  lls                  Link-local Signaling (LLS) support
  message-digest-key   Message digest authentication password (key)
  mtu-ignore           Ignores the MTU in DBD packets
  multi-area           Set the OSPF multi-area ID
  network              Network type
  prefix-suppression   OSPF prefix suppression
  priority             Router priority
  resync-timeout       Interval after which adjacency is reset if oob-resync is not started
  retransmit-interval  Time between retransmitting lost link state advertisements
  shutdown             Set OSPF protocol's state to disable under current interface
  transmit-delay       Link state transmit delay
  ttl-security         TTL security check

Result:
Interface-specific OSPF activation and the planned interface cost/network-type
controls are exposed by the IOSvL2 image.


6. OSPF ECMP path limit

maximum-paths ?

Observed:

Verification:

======================================================================
Overall result
======================================================================

No platform capability blocker was identified for the approved HQ design based on
the representative IOSvL2 and IOSv checks performed during Phase 01.

Capabilities demonstrated at parser/platform level:
- Layer 2 EtherChannel / LACP active-passive modes
- Rapid PVST+
- Routed physical interfaces on IOSvL2
- HSRP command family
- Interface-specific OSPF activation
- OSPF point-to-point network type
- OSPF interface cost control
- Explicit OSPF router IDs
- Passive-interface default policy
- OSPF maximum-paths with support for four-path ECMP
- OSPF area-range command family

These checks establish platform suitability only. Actual protocol operation,
adjacencies, failover, convergence, path selection, summarisation and failure
behaviour remain subject to the later implementation and verification phases.
